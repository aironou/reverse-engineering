# android code map

## input

to map APK entrypoints, use the JSON files generated by `android-apk-inspect`
and `android-code-index` for the same APK. define their paths as
`{{inspect_file}}` and `{{index_file}}`.

## flow

### load inputs

using `terminal`, read `{{inspect_file}}` and `{{index_file}}` as JSON. keep the
values available during this flow. set `package_name` to the `name` value from
the inspection JSON (`inspect.name`).

### map application entrypoint

if `inspect.application.name` exists, create an entrypoint for the declared
application class using this schema:

```json
{
    "inspect_name": "{{application.name}}",
    "inspect_type": "application",
    "index_id": null,
    "callables": []
}
```

#### relate application to indexed type

find the object in `index.types` whose `qualified_name` exactly matches
`application.name`.

if exactly one type matches, set the entrypoint's `index_id` to that type's
`id`. if no type matches or more than one type matches, set `index_id` to
`null`.

#### relate application callbacks

consider these Application callback names, in this order: `onCreate`,
`onTerminate`, `onConfigurationChanged`, `onLowMemory`, and `onTrimMemory`.

for each name in this list, find the objects in `index.callables` whose
`qualified_name` exactly matches `application.name` followed by `.` and the
callback name. include every matching callable in the entrypoint's `callables`
list, preserving the callback order above and the index order among overloads.
create each item as below:

```json
{
    "index_name": "{{callable.name}}",
    "index_id": "{{callable.id}}"
}
```

if the application type did not match an indexed type, set `callables` to an
empty list. include only callbacks present in the index. if a callable has no
`qualified_name`, it does not match.

append the application entrypoint to the beginning of the `entrypoints` list.
if `inspect.application.name` does not exist, do not create an application
entrypoint.

### map activity entrypoints

for each object in `inspect.activities`, create an entrypoint with the schema
below:

```json
{
    "inspect_name": "{{activity.name}}",
    "inspect_type": "activities",
    "exported": "{{activity.exported}}",
    "enabled": "{{activity.enabled}}",
    "triggers": [],
    "index_id": null,
    "callables": []
}
```

set `triggers` from `activity.intent_filters`. for each intent filter, create
an object as below:

```json
{
    "type": "intent-filter",
    "actions": ["{{intent_filter.action}}"],
    "categories": ["{{intent_filter.categories}}"],
    "data": ["{{intent_filter.data}}"]
}
```

if the activity has no intent filters, set `triggers` to an empty list.

#### relate activity to indexed type

find the object in `index.types` whose `qualified_name` exactly matches
`activity.name`.

if exactly one type matches, set the entrypoint's `index_id` to that type's
`id`. if no type matches or more than one type matches, set `index_id` to
`null`.

#### relate activity callbacks

consider these Activity lifecycle callback names, in this order:
`onCreate`, `onRestart`, `onStart`, `onResume`, `onPause`, `onStop`, and
`onDestroy`.

for each name in this list, find the objects in `index.callables` whose
`qualified_name` exactly matches `activity.name` followed by `.` and the
callback name. include every matching callable in the entrypoint's `callables`
list, preserving the callback order above and the index order among overloads.
create each item as below:

```json
{
    "index_name": "{{callable.name}}",
    "index_id": "{{callable.id}}"
}
```

if the activity type did not match an indexed type, set `callables` to an empty
list. include only callbacks present in the index. if a callable has no
`qualified_name`, it does not match.

append each activity entrypoint to the `entrypoints` list, preserving the
order of `inspect.activities`.

### map activity-alias entrypoints

for each object in `inspect.activity_aliases`, create an entrypoint with the
schema below:

```json
{
    "inspect_name": "{{activity_alias.name}}",
    "inspect_type": "activity_aliases",
    "target_activity": "{{activity_alias.target_activity}}",
    "triggers": [],
    "index_id": null,
    "callables": []
}
```

set `triggers` from `activity_alias.intent_filters`, using the same
`intent-filter` object structure defined for Activities. if the alias has no
intent filters, set `triggers` to an empty list.

#### relate activity-alias to indexed type

`activity-alias` names an alias and does not identify a class. find the object
in `index.types` whose `qualified_name` exactly matches
`activity_alias.target_activity`.

if exactly one type matches, set the entrypoint's `index_id` to that type's
`id`. if no type matches or more than one type matches, set `index_id` to
`null`.

#### relate activity-alias callbacks

use the Activity lifecycle callback names defined in `relate activity
callbacks`. for each callback name, find the objects in `index.callables` whose
`qualified_name` exactly matches `activity_alias.target_activity` followed by
`.` and the callback name. include every matching callable in the alias
entrypoint's `callables` list, preserving the callback order and the index
order among overloads. use the callable object structure defined for Activity
callbacks.

if the target activity type did not match an indexed type, set `callables` to
an empty list. include only callbacks present in the index. if a callable has
no `qualified_name`, it does not match.

append each activity-alias entrypoint to the `entrypoints` list, preserving
the order of `inspect.activity_aliases`.

### map service entrypoints

for each object in `inspect.services`, create an entrypoint with the schema
below. copy each listed value from the service object in the inspection JSON.

```json
{
    "inspect_name": "{{service.name}}",
    "inspect_type": "services",
    "exported": "{{service.exported}}",
    "permission": "{{service.permission}}",
    "process": "{{service.process}}",
    "foreground_service_types": ["{{service.foreground_service_types}}"],
    "isolated_process": "{{service.isolated_process}}",
    "stop_with_task": "{{service.stop_with_task}}",
    "direct_boot_aware": "{{service.direct_boot_aware}}",
    "triggers": [],
    "index_id": null,
    "callables": []
}
```

set `triggers` from `service.intent_filters`. for each intent filter, create an
object as below:

```json
{
    "type": "intent-filter",
    "actions": ["{{intent_filter.action}}"],
    "categories": ["{{intent_filter.categories}}"],
    "data": ["{{intent_filter.data}}"]
}
```

if the service has no intent filters, set `triggers` to an empty list.

#### relate service to indexed type

find the object in `index.types` whose `qualified_name` exactly matches
`service.name`.

if exactly one type matches, set the entrypoint's `index_id` to that type's
`id`. if no type matches or more than one type matches, set `index_id` to
`null`.

#### relate service callbacks

consider these Service callback names, in this order: `onCreate`, `onStart`,
`onStartCommand`, `onBind`, `onUnbind`, `onRebind`, `onTaskRemoved`, `onTimeout`,
`onDestroy`, `onConfigurationChanged`, `onLowMemory`, and `onTrimMemory`.

for each name in this list, find the objects in `index.callables` whose
`qualified_name` exactly matches `service.name` followed by `.` and the
callback name. include every matching callable in the entrypoint's `callables`
list, preserving the callback order above and the index order among overloads.
create each item as below:

```json
{
    "index_name": "{{callable.name}}",
    "index_id": "{{callable.id}}"
}
```

if the service type did not match an indexed type, set `callables` to an empty
list. include only callbacks present in the index. if a callable has no
`qualified_name`, it does not match.

append each service entrypoint to the `entrypoints` list, preserving the order
of `inspect.services`.

### generate map file

create a JSON file at `projects/android/{{package_name}}/artifacts/analysis
/map/{{APK file name}}.json`, where `package_name` is `inspect.name` and 
`APK file name` is the basename of `{{index_file}}` without its `.json`
extension.

the file must contain only the following object:

```json
{
    "entrypoints": ["{{entrypoint}}"]
}
```

append each generated entrypoint object to the `entrypoints` array; the
placeholder above represents one entrypoint in the output structure.

## verification

after processing this skill flow:

- confirm that `projects/android/{{package_name}}/artifacts/analysis/map`
  exists;
- confirm that `projects/android/{{package_name}}/artifacts/analysis/map
  /{{APK file name}}.json` exists and contains the entrypoints JSON;
- confirm that this JSON file is the only file created by this skill.
